# OurList 1.0.8(9) 수정 및 검증 — 2026-11-06

## CONFIRMED

- Firebase 기존 공개 테스트 규칙을 인증된 두 기기만 접근하는 규칙으로 교체했다. 기존 /rooms 데이터는 지우지 않고 접근을 차단했다. 새 privateRooms와 pairRequests는 기기별 익명 인증, 방 생성자 승인 및 양쪽 확인번호 대조를 사용한다. app_version은 공개 읽기/관리자 쓰기만 허용한다.
- 기존 연결은 두 휴대폰 모두 업데이트 후 새 코드로 한 번 다시 연결한다. 로컬 공동·하트·개인·비밀 목록은 유지한다. 기존 Release 서명과 keystore를 변경하지 않았다.
- 코드 충돌은 ETag 조건부 생성으로 보호하고, 승인 없는 가입/파트너 교체/다른 기기 사칭/닫힌 방 접근을 차단한다. 인증 갱신 실패를 새 계정 생성으로 숨기지 않는다.
- 동기화는 실제 변경 필드와 이전 값으로 병합·충돌 판정한다. 체크리스트 삭제가 되살아나거나 이동한 항목이 상대 기기에서 숨는 문제를 수정했다. 로컬 변경/작업 기록 및 수신 반영/확인은 Room 트랜잭션으로 묶었다. Room 1→2 비파괴 migration을 사용한다.
- HTTP 실패와 누락 토큰은 성공/빈 목록으로 바꾸지 않는다. Drive 전체 페이지, 인증 401 재발급, 원자적 multipart 업로드를 구현했다. 연결 승인 시 최초 스냅샷과 적용 작업 ID를 먼저 가져온다.
- 암호화 v2 백업은 비밀번호와 당시 복구 코드 모두로 복원 가능하며 v1 호환을 유지한다. 개인/비밀만 복원하고 ID 충돌·중복을 검증한다. appData 권한/조회/복원/7개 보존, 재시도/최근 오류를 구현했다.
- 평문 폴더 백업은 공동·하트만 포함한다. 내보내기는 공동·하트 기본 선택, 개인/비밀/휴지통 명시 선택으로 바꿨다. CSV 수식 입력과 OS 자동 백업도 제한했다.
- 편집 초안 회전 보존, 비용 범위 오류와 저장 차단, 저장 재시도, 알림 상세 이동, foreground 10초 수신 동기화, 체크박스 선택 상태, 큰 글씨 버튼/가로 스크롤 필터를 수정했다.
- 다음 APK 다운로드는 SHA-256/크기/패키지/버전/기존 서명을 검증한다. 일반 앱 내 설치는 Android의 설치 확인과 출처 허용이 필요하다.
- 모든 신규 APK는 scripts/build_and_archive.ps1로 사용자 확정 경로 G:\내 드라이브\03_앱개발\ourlist에 즉시 복사하고 크기·SHA-256을 대조했다. 기존 파일은 보존했다. 실제 클라우드 동기화는 UNKNOWN.

## 검증

- Debug 59 / Release 59 JVM 테스트 통과, Release lint Error/Fatal 0, git diff --check 통과.
- 공식 Firebase Auth+RTDB 에뮬레이터 보안 33개 통과. 운영 서버에서도 새 시험 방/임시 익명 계정 3개로 같은 33개 통과 후 해당 시험 데이터와 계정만 삭제했다. 기존 사용자 방은 조회·수정·삭제하지 않았다.
- API 36: 기존 1.0.7→1.0.8 업데이트 시 AuditItem 보존과 Room migration 성공. 초안 회전 보존, 비용 overflow 저장 차단, 접근성 checkbox 상태 확인.
- 새 데이터 없는 별도 OurListSecureQA 에뮬레이터에서 Release/Debug를 독립 기기로 사용해 승인 전 확인번호, 생성자 승인, 상대 목록 수신, 공동→하트 이동 수신을 확인했다. 이는 실제 두 물리 휴대폰 검증은 아니다.
- 200% 글씨에서 동기화 버튼과 가로 스크롤 필터 확인. 수동 암호화 백업 파일 저장·선택과 복구 코드로 개인 항목 1개 복원 성공.
- 선택 증거: evidence/, 자동 검사 XML 및 firebase-*-security-results.json. 원본 공개 규칙 백업은 firebase-live-rules-before.json. 보안 규칙 원복 대상으로 사용하지 않는다.
